# graft-consumer example

Proves the point of the Graftcode surface added in this PR: integrators no longer
have to hand-write an API client (fetch calls, response types, endpoint URLs) for
`alfa-leetcode-api`. They `npm install` a generated, strongly-typed client and call
methods directly.

This directory installs the real client generated by the live `gg` gateway (see
`../../GRAFTCODE.md` for how to run it) and calls it from `smoke-test.mjs`.

## Before: hand-written REST consumer

Today, getting upcoming contests means writing your own `fetch` call, guessing/
copying the response shape from the README or Swagger, and hand-rolling types:

```ts
// Hand-written by every integrator, kept in sync manually.
interface RawContest {
  title: string;
  titleSlug: string;
  startTime: number; // <- raw unix-epoch seconds, easy to mis-handle
  duration: number;
  isVirtual: boolean;
  containsPremium: boolean;
}

interface UpcomingContestsResponse {
  count: number;
  contests: RawContest[];
}

const res = await fetch('https://alfa-leetcode-api.onrender.com/contests/upcoming');
const data: UpcomingContestsResponse = await res.json(); // no compile-time guarantee this matches reality

for (const contest of data.contests) {
  const startsAt = new Date(contest.startTime * 1000); // manual epoch-seconds conversion
  console.log(contest.title, startsAt.toISOString());
}
```

If the API adds/renames/reshapes a field, this silently drifts out of sync until
something breaks at runtime.

## After: typed graft call

```js
import { Contest, GraftConfig, LeetCodeContests } from '@graft/npm-alfa-leetcode-api-graft';

GraftConfig.host = 'ws://<gateway-host>:<port>/ws';
GraftConfig.stateless = false;

const upcoming = await LeetCodeContests.getUpcomingContests();
const first = new Contest(upcoming[0]);

console.log(await first.title, await first.startsAt); // startsAt is already ISO-8601
```

No endpoint URL, no response shape to guess, no manual timestamp conversion - the
method name, parameter types and `Contest` fields all come from
`src/services/LeetCodeContests.ts` and `src/services/dto.ts` in this repo, and a
type mismatch there is a compile-time error for the client, not a runtime surprise.

## Running this example

1. Bring up the graft gateway from the repo root: `docker compose up graft`.
2. Grab the current install command (the registry GUID rotates per gateway
   restart since no `--projectKey` is configured):

   ```bash
   curl http://localhost:8080/npm
   ```

3. Install it here:

   ```bash
   cd examples/graft-consumer
   npm install --registry https://grft.dev/<GUID>__free @graft/npm-alfa-leetcode-api-graft@1.0.0
   ```

4. Run it:

   ```bash
   node smoke-test.mjs
   ```

You should see the same upcoming contests `/contests/upcoming` returns, already
typed and with `startsAt` as ISO-8601.
